# 分两阶段交付：v1 全屏启动台，v2 桌面分区

deskmind 的最终形态仍然是带 AI 的桌面美化软件，但交付分成两个阶段：

- **v1 — 启动台**：热键唤出的全屏界面，AI 把启动项分好组，用户在其中浏览、检索、启动。不触碰桌面本身。
- **v2 — 桌面分区**：把同一套分区画到桌面上，用 AI 整理的结果驱动原生桌面图标的位置。这才是完整的桌面美化产品。

## 为什么改

设计阶段产出的界面是一个全屏启动台，与此前 ADR 假定的「桌面上的半透明分区卡片」是两个产品形态。评估后决定以设计为准，并把桌面分区排到 v2。

**决定性理由是风险排序。** 启动台不需要 WorkerW 挂载，不需要 `IFolderView` 跨进程移动原生图标，不需要迁就 Windows 桌面图标网格——v1 因此没有任何一项高风险的 Win32 工作。而产品的核心假设「AI 分组的质量足够好，好到用户觉得省事」在启动台里同样能被完整验证。

先用低风险的载体验证高风险的假设，再去做高风险的载体。反过来做，可能在假设被证伪之前就先耗死在 Win32 调试上。

## 两个阶段共用什么

这是分阶段成本很低的原因——v2 不是重写，是给同一套核心加一个渲染目标：

- 启动项的枚举与索引
- 分区的数据模型与持久化
- AI 整理层（见 ADR 0007）
- 分区建议与首次运行（见 ADR 0009）
- 设置界面
- 壁纸取色与配色系统（见 ADR 0012）

v2 新增的只有：桌面层窗口挂载（WorkerW）、原生图标位置控制（`IFolderView`，见 ADR 0008）、以及分区在桌面上的绘制。

## v1 功能边界

**做**：启动项枚举（开始菜单快捷方式目录与桌面）与图标提取；分区的创建、重命名、删除、排序；AI 整理与撤销；分区建议与首次运行流程；搜索与启动；固定；托盘菜单与全局热键；壁纸切换与取色配色；设置（API key、模型、置信度阈值、开机自启、热键）。

**不做**：桌面层渲染与原生图标移动（v2）；AI 生成壁纸与配色方案（见 ADR 0003）；动态壁纸；语义搜索；应用运行状态监测；本地模型；插件系统。

关于运行状态：设计稿的磁贴上有「运行中」指示。它需要持续轮询进程列表，属于额外的复杂度，v1 不做，磁贴上不出现该状态。

## Consequences

v1 的磁贴由 deskmind 自己绘制，因此不受任何图标外观限制——可以自由设计光晕、固定角标、悬停效果。这条自由在 v2 的桌面分区里不存在（那里是系统原生图标）。**两个阶段的视觉语言会因此不完全一致**，这是可接受的，因为它们是两个不同的表面。

验收标准不变：整理后需要用户手动调整的启动项不超过 20%。
