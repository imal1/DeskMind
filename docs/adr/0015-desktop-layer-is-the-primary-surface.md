# 启动台常驻桌面层，浮层降为辅助表面

> **Status**: 由 ADR-0017 修订。「桌面表面是唯一主表面」有效；**`SetParent` 到桌面层的做法作废**——WebView2 挂上去之后收不到任何鼠标消息（S3 验的是记事本，不是 WebView2）。热键浮层一并取消。

deskmind 的主表面是一个**常驻桌面层**：窗口在启动时 `SetParent` 到桌面层，一直可见，其他应用正常盖在它上面。用户看向桌面时看到的就是 deskmind——它不再是一个需要唤出的浮层。

热键唤出的浮层保留，但角色变了：当用户正在其他应用里工作、不想最小化一切时，用它临时取用启动台。

## 为什么改

原设计（ADR 0010 的后继形态）是「热键唤出的全屏浮层」。但产品意图始终是替代桌面本身——一个需要唤出的东西不是桌面，是启动器。ADR 0013 已经把「桌面层」排进 v2，S3 的验证结果说明它现在就能做，而且比 ADR 0008 计划的那条路便宜得多：我们自己画磁贴，不需要 `IFolderView` 去搬 explorer 的原生图标。

## S3 的实测结论

在桌面层上：渲染正常、其他应用正常遮挡、鼠标点击可用、Win+D 后仍在、最小化所有窗口后可见。

**键盘不会自动到达**，因为键盘消息只发给活动顶层窗口的焦点窗口，而 `SetParent` 之后活动顶层窗口是桌面。必须在用户点击时显式争取焦点：连接输入队列（`AttachThreadInput`）、对顶层父窗口 `SetForegroundWindow`、对子窗口 `SetFocus`、断开。实测有效。

这套手法本身是脆的，Windows 故意让抢焦点变难。但有一条规则对我们有利：**限制对刚收到用户输入的进程放开**，而这段代码只在用户点击我们自己的窗口时运行。完整背景见 `spikes/s3-workerw/FINDINGS.md`。

## 两个窗口，一份界面

- **`desktop`** —— 挂在桌面层，常驻可见，永不隐藏。点击时争取键盘焦点。
- **`launchpad`** —— 普通顶层窗口，热键唤出，失焦即隐藏。

两者渲染同一份前端，靠窗口 label 判断模式。选择两个窗口而不是「同一个窗口在两种模式间切换」，是因为切换意味着运行时反复 `SetParent` 进出桌面层，每次都要重建焦点状态——两个窗口各自状态稳定，代价只是多一份内存。

## 对既有 ADR 的影响

**ADR 0014（全屏置顶窗口必须失焦即隐藏）适用范围收窄到 `launchpad` 窗口。** 那条约束的前提是「全屏 + 置顶 + 失焦仍可见会埋掉桌面」；`desktop` 窗口不置顶、不抢占，被其他应用正常遮挡，因此不适用——而且它必须永不隐藏，否则就没有桌面了。

**ADR 0008（移动原生图标）仍然推迟。** S3 中挂上去的窗口位于桌面图标**之上**，这对启动台正好（我们自己画磁贴），但 v2 若要做「分区卡片衬在原生图标之下」，还需要继续找真正位于图标之下的那一层。

## Consequences

桌面图标会被 deskmind 盖住。这是预期效果而非缺陷——但意味着用户失去了原生桌面图标的使用方式，所以磁贴必须覆盖它原本的用途（打开、右键菜单、拖放）。右键菜单已有；拖放尚无。

如果争取焦点在某些场景下失效（远程桌面、UAC 提权窗口活动期间、部分全屏游戏），桌面层会退化为只能用鼠标。届时的降级路径是提示用户用热键唤出浮层，而不是让键盘看起来坏掉。
