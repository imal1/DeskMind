# 无后端，用户自带 API key

deskmind 没有服务端。用户填入自己的模型 API key，客户端直连模型厂商。

## Considered Options

**提供托管服务**（我们出 key，用户开箱即用）体验最好，但需要公司主体、收款能力和持续的账单支出，与「开源、面向发烧友、不商业化」的定位直接冲突。

**内置本地小模型做分类**能做到完全不联网，是隐私最优解，但会显著抬高 v1 的实现难度和分发体积。推迟到 v2 作为可选项提供给真正在意隐私的用户。

## Consequences

这个选择一次性消掉了三个问题：不需要写后端、不需要管账单、**用户数据从头到尾不经过我们的服务器**。

后一点尤其重要。整理功能需要把桌面项的文件名交给模型判断，这是敏感数据；在无后端架构下，这些数据是用户用自己的 key 发给模型厂商的，deskmind 不是数据的接收方也不是中转方。隐私问题因此不构成架构约束，只需要在 README 中把数据流向说明清楚。
