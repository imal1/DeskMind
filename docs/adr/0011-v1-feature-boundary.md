# v1 功能边界：明确不做的事

> **Status**: 已被 ADR-0013 取代——功能边界按启动台形态重划，见 ADR-0013。

本 ADR 记录 v1 刻意排除的功能与各自的理由。这些「不做」会被反复质疑，写下来是为了不必每次重新辩论。

## 壁纸：只做静态设置与取色，不做壁纸引擎

**做**：设置静态壁纸（`SystemParametersInfo` 配合 `SPI_SETDESKWALLPAPER`）；读取当前壁纸、提取主色，用于自动生成分区配色。

**不做**：动态壁纸、视频壁纸、shader 壁纸、壁纸库或壁纸商店。

这条界线容易被误读成「不碰壁纸」，那是错的。做一个壁纸引擎意味着与 Wallpaper Engine 正面竞争，我们不可能赢，也没有差异化。但从壁纸提取主色是必须做的：分区绘制在桌面上，如果配色与用户的壁纸不搭，整个产品看起来会像贴上去的补丁。取色让分区长在用户的壁纸上，是纯粹的美化收益，成本约两天。

## 启动器：做搜索启动，不做语义搜索

**做**：热键唤出搜索框；索引来源是桌面项与开始菜单快捷方式目录（`%ProgramData%` 与 `%AppData%` 下的 Start Menu\Programs）；模糊字符串匹配，回车启动。

**不做**：语义搜索（「上周客户发的那个报价单」）、文件内容搜索、可扩展的搜索源。

一个不能搜索启动的「启动器」是自相矛盾的，所以搜索是 v1 的身份底线。枚举已安装软件只需扫描两个快捷方式目录，约 50 行，成本远低于它带来的完整度。语义搜索是差异化功能，但它依赖向量或额外的模型调用，推迟到 v2。

## 其他排除项

- **分区折叠** —— 技术上不可行，见 ADR 0008
- **自动触发整理** —— 实现成本被低估（文件系统监视、防抖、竞态），且自动出错的心理成本远高于手动，v2 再做
- **AI 生成壁纸与配色方案** —— 见 ADR 0003
- **场景切换** —— `CONTEXT.md` 中已定义该词，但 v1 不实现
- **本地模型** —— 见 ADR 0006
- **插件系统** —— 没有用户量的插件生态是空的

## Consequences

加上壁纸取色与搜索启动后，v1 从「很像 Fences」变成一个形态完整的产品，代价约一周。

但核心假设没有变：产品成败取决于「点一下，桌面自己整齐了」那一瞬间是否足够好。上述任何功能都不能替代它，验收标准仍然是整理后需要手动调整的桌面项不超过 20%。
