# 液态玻璃是目标本身，不是四类效果里的一类

> 修订 ADR-0016。渲染分层的判断不变，为"先跑起来"做的几项取舍作废。

ADR 0016 把想要的效果拆成四类，取其二先做，并为了先跑起来定了一串省事的选择：裸 WebGL2、单 pass、捕获限速半分辨率 30fps、玻璃是"你注意找才看得出来"的程度。

那套取舍在当时是对的——不知道需要哪些抽象之前先买抽象，方向是反的。但它把**手段的边界写成了目标的边界**，而三轮人工验收都不通过，根因正落在那些边界上。

**目标是完整实现 iOS/tvOS 27 的那个材质。** 不是四类效果里的一类，不是在成本里找一个可接受点。

## 因此作废

**"玻璃应该是你注意找才看得出来的"。** ADR 0016 引用设计"不要霓虹、边框 8–20% 白"推出这一条，着色器里因此写着"深度完全来自折射"，issue #4 把它描述成"极清玻璃"。这个目标定错了：那个材质的主体是有厚度的浑浊介质，**模糊是它的本体，不是修饰**。

**"先不用库，裸 WebGL2 / 等多 pass 写起来费劲了再引 OGL"。** 判断本身没错，但它被当成了不许多 pass 的理由。需要离屏目标就上，评估的是 render-to-texture、pass 编排、uniform 管理三件事，不是渲染器本身。什么时候真的需要，记在 #16。

**"捕获限速 30fps、半分辨率，因为结果只透过磨砂镜片看"。** 后半句不成立了：斜面是清透的，上面还有透镜压缩和会动的高光，那一圈恰恰是细节最要紧的地方。见 #22。

**四类效果的优先级表。** A（转场与微交互）已完成，C（真 3D）已按"记录已经想过"关闭，B 与 D 合并成了现在这一套。表格不再描述任何待办。

**三套背景特效。** 雾影与纯净已删除，只留下照着那代 chrome 做的那一套（`b73c7d6`）。ADR 0016 里"每种模式各自怎么veil"的描述随之作废。

## 不作废

**"被遮挡时 GPU 占用 0%，一帧都不画"。** 保留，且不接受为观感放宽。它不牺牲任何东西——没人在看的时候不画，用户永远感知不到。这是纯赚。

**"空闲可见 1–2%"。** 保留。它描述的是没有面板的常驻状态，那个状态一天二十四小时都在发生。

但要补一条 ADR 0016 没有的：**面板打开是第三种状态**，它一直没有线，也一直没被量过——因为唤出面板的热键在 ADR 0017 删掉启动台时一并删除了，而设置面板里那行字留了下来，于是有三年没人能进到那个状态去量它。第一次量到 **38.25%**，空闲是 1.87%。

那不是一条要放宽的线，是缺陷，而且跟多 pass 无关：玻璃层在给整块屏幕着色（1980 万片元）而面板只占 2%；面板落定之后仍按显示器刷新率重画；背景层在玻璃出现时跳到全分辨率，那些细节又在半分辨率的捕获里当场被扔掉。修完是 6.19% 再往下。

**DOM 仍然是权威**，布局、文字、输入、命中测试、无障碍全部留在 DOM。ADR 0016 否决整个 UI 进 canvas 的决定性理由是中文输入法，那是功能要求不是审美取舍，不在本文修订范围内。

## Consequences

验收的问法变了：不再是"这一版调得好不好、该往哪个旋钮偏"，而是"离那个材质还差什么"。前者三轮都得到同一个答案——"不对，但说不出哪里"——因为缺的东西不在旋钮的量程里。

差距因此可以逐条列出来并逐条消掉：折射从二维偏移换成带厚度的透镜（#17）、高光从各处等亮换成有方向且会滑动（#18）、磨砂从取一级 mip 换成螺旋采样。剩下的挂在 #20、#21、#22。

判断"到了没有"要用验收台（#15），不要用记忆。人对绝对量没有判断力，对并排差异才有。
