# 没有主窗口，全部交互发生在桌面与浮层上

> **Status**: 已被 ADR-0013 取代——v1 的启动台是一个全屏主界面。

deskmind 不提供常规意义上的应用主窗口。用户界面由三部分构成：绘制在桌面层上的分区本身、托盘图标与其菜单、以及若干按需唤出的浮层（设置、搜索、整理结果）。

## Considered Options

**提供一个主窗口**（在窗口里管理分区、查看整理历史、调整设置）是桌面软件的默认形态，信息架构也更容易组织。

拒绝它的理由是产品的身份认知：deskmind 的形态就是桌面本身，它不应该有一个「需要打开的 app」。用户不会想跑到某个窗口里去管理分区——分区就在桌面上，直接拖就行。一旦有了主窗口，产品就从「你的桌面」退化成「一个管理桌面的工具」。

## Consequences

工作量显著降低：不需要设计窗口内导航、页面路由，也不需要一整套窗口级信息架构。v1 只需要设计分区本身，加上设置、搜索、整理结果三个浮层。

代价是设置项一旦变多会挤在浮层里。v1 的设置只有 API key、模型、开机自启和热键，一个浮层足够；等设置项增长到浮层装不下时，应当重新审视这条 ADR，而不是无限堆叠浮层。
