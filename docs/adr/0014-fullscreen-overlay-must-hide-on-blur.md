# 全屏置顶窗口必须失焦即隐藏

启动台窗口是 `fullscreen` + `alwaysOnTop` + `skipTaskbar`。因此它一旦失去焦点仍然可见，就会盖住这台电脑上的所有其他应用，而且**没有任务栏按钮可以点、没有标题栏可以关**——用户唯一的出路是从托盘退出，或者重启电脑。

所以：**窗口失去焦点时必须自行隐藏。** 这不是一个交互偏好，是这套窗口配置下的安全约束。

## 为什么写下来

这段逻辑看起来像多余的便利功能，很容易被后来者当作噪音删掉，或者在重构焦点处理时顺手丢掉。它实际承担的是兜底责任：任何一条"让窗口可见但没有焦点"的代码路径——无论是新加的功能、异常分支还是竞态——都会导致桌面被埋。有了这条兜底，那一整类 bug 的后果从灾难降级为闪一下。

这条约束是被一个真实 bug 换来的：首次运行流程为了自我介绍主动调用了 `show()`，但结束时只隐藏了面板、没有隐藏窗口。结果引导做完之后，一张全屏幕的浮层永久停在最上层，所有应用都看不见了，重启才恢复。

## 例外

首次运行流程与设置面板打开时不自动隐藏——用户可能切到浏览器去取 API key，回来时不该发现填了一半的表单没了。这两处都有自己的显式出口（「跳过」「开始用」「保存」「Esc」），不依赖失焦。

## 顺带的好处

失焦即隐藏本来就是启动器的标准行为，Spotlight 和 Alfred 都如此。所以这条安全约束不需要为了安全牺牲手感，两者刚好一致。

## Consequences

任何未来新增的、会让窗口可见的入口，都不需要单独考虑"用完怎么收起"——兜底已经在。但反过来，任何想让窗口在失焦后保持可见的需求（例如把某个面板做成可以边看边操作其他程序），都必须先推翻这条 ADR，并说明如何避免上述后果。
