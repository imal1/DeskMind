# 交给设计前必读

界面的一部分**不是 CSS 画的**。改样式之前先看清哪些是、哪些不是，否则会出现"改了没反应"或者"改完把效果盖掉了"。

## 谁画了什么

| 元素 | 由谁绘制 | 怎么改 |
|---|---|---|
| 壁纸、雾/光带、背景遮罩 | **WebGL 着色器** | `src/background.ts` 里的 GLSL |
| 面板的整个表面：折射、磨砂、压暗、边线、投影（搜索框等） | **WebGL 着色器** | 同上，`RIM` / `bend` / `darkness` / `lod` |
| 面板的圆角尺寸、内部文字与控件 | CSS | `index.html` |
| 导航条、标签、按钮、磁贴 | CSS | `index.html`，按 `body[data-effect]` 分三套 |
| 详情面板、右键菜单、toast | CSS | 同上 |

**关键**：搜索面板背后那层弯曲的壁纸是着色器画的，画在 DOM 之下。所以

- 着色器接管一块面板时，面板**整个表面**都归它：磨砂、压暗、边线、投影都在着色器里。DOM 只留内容。`.panel.glassed` 因此把 `background`、`backdrop-filter`、`border-color`、`box-shadow` 全部归零——这不是遗漏，两套系统各画半块面板正是双层边框和浑浊投影的来源
- 所以**别给 `.panel.glassed` 加回 CSS 底色或 `backdrop-filter`**，那是直接把折射盖死。要更模糊调 `lod`（1.2 → 5.0），要更暗调 `darkness`（0.16 → 0.54），都在 `src/background.ts`
- 基础 `.panel` 上的 `backdrop-filter` 只在**纯净**下生效。那个模式着色器不画玻璃，`glassed` 不会挂上去，面板退回自己的 CSS 背景
- 改面板圆角要**同步**：着色器按 `getBoundingClientRect()` 和 `border-radius` 取矩形，圆角对不上会露出双层边框

## 两条会咬人的规则

**带玻璃的面板不能做位移入场。** 着色器拿到的是一张 CSS 像素快照，跟不了 CSS 动画——面板一边滑一边亮，玻璃就会停在旧位置，或者要等动画结束才出现（那就是一秒的延迟感）。所以 `#search` / `#settings` / `#first` 只淡入不位移。想要位移必须改成每帧重读矩形，那是另一笔开销。

**这份 CSS 里 ID 选择器很多，覆盖样式要盯优先级。** 已经栽过两次：`.hide` 被 `#ctx { display:flex }` 压过导致菜单关不掉；`[data-effect="highlight"] .pill` 被 `#searchbtn` 压过导致高亮模式下按钮还是暗的。按状态覆盖时，选择器要写到同等或更高的特异度。

## 三套特效

设置里的「背景特效」切换 `body[data-effect]`，三套都要顾：

- **`highlight`（默认）** —— 光带掠过壁纸，背景压暗较轻。导航条走 iOS 27 那种"清透 + 边缘亮线"，不是磨砂
- **`fog`** —— 缓慢流动的雾，背景压暗较重。导航条是磨砂
- **`none`** —— 只有壁纸。**导航条没有任何底和模糊，面板退回自己的 CSS 背景**（因为着色器在这个模式下不画玻璃）

改任何一套，另外两套都要过一遍。

## 布局是响应式的，别用固定坐标

原设计稿是 1600×900 的固定尺寸稿，所有坐标是死的。**实际运行在带鱼屏上**（实测 2600 宽以上），所以现在全部用 `clamp()` 和 `vw`。

已知未解决：**超宽屏中间是空的**。左侧详情 + 底部导轨只有两个锚点，16:9 上填得满，21:9 上就散了。设计稿右侧原本有个助手面板（`right:56px; top:146px; width:352px`），一直没做——**它在带鱼屏上是结构性的，不是装饰**。

## 两个表面共用一份界面

同一个页面渲染两个窗口：常驻桌面的 `desktop` 和热键唤出的 `launchpad`。改样式两边都会变。

## 性能是硬约束

桌面层一天二十四小时在屏幕上。着色器循环在被遮挡时会完全停止（ADR 0016 定的硬线：遮挡时 GPU 占用 0%）。

**不要加持续运行的 CSS 动画到常驻元素上**——它绕过了那套暂停逻辑。入场动画、hover 过渡都没问题，那些是有始有终的。
