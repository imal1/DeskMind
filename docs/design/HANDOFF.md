# 交给设计前必读

界面的一部分**不是 CSS 画的**。改样式之前先看清哪些是、哪些不是，否则会出现"改了没反应"或者"改完把效果盖掉了"。

## 目标：完整的 Liquid Glass

面板玻璃的目标是**完整实现 iOS/tvOS 27 的那个材质**，不是在成本里找一个可接受点。这句话优先于本文档其余部分，也优先于 ADR 0016 里那些为了先跑起来而做的取舍（见 ADR 0018）。

一条推论，因为它曾经被写反过：**模糊是这个材质的主体，不是加在上面的修饰。** 着色器里一度写着"深度完全来自折射"、把这一档描述成"极清玻璃"——那是错的，已经改掉。

## 谁画了什么

| 元素 | 由谁绘制 | 怎么改 |
|---|---|---|
| 壁纸、光带、背景遮罩 | **WebGL 着色器** | `src/background.ts` 里的 GLSL |
| 面板的整个表面：折射、磨砂、压暗、高光、边线、投影 | **WebGL 着色器** | 同上，参数见 `DEFAULT_TUNING` |
| 面板的圆角尺寸、内部文字与控件 | CSS | `index.html` |
| 导航条、标签、按钮、磁贴 | CSS | `index.html` |
| 详情面板、右键菜单、toast | CSS | 同上 |

**关键**：搜索面板背后那层弯曲的壁纸是着色器画的，画在 DOM 之下。所以

- 着色器接管一块面板时，面板**整个表面**都归它。DOM 只留内容。`.panel.glassed` 与 `#ctx.glassed` 因此把 `background`、`backdrop-filter`、`border-color`、`box-shadow` 全部归零——这不是遗漏，两套系统各画半块面板正是双层边框和浑浊投影的来源
- 所以**别给它们加回 CSS 底色或 `backdrop-filter`**，那是直接把折射盖死
- 改面板圆角要**同步**：着色器按 `getBoundingClientRect()` 和 `border-radius` 取矩形，圆角对不上会露出双层边框

## 玻璃的参数都在一个地方

不要在 GLSL 里找散落的常数改，它们已经全部提成 uniform，集中在 `src/background.ts` 的 `DEFAULT_TUNING`：

| 参数 | 管什么 |
|---|---|
| `ior` / `thickness` | 斜面的折射：折射率与板厚。厚度决定弯多远 |
| `rim` | 斜面有多宽 |
| `dispersion` | 三个通道的折射率差。真色散，不是把一个偏移乘三个长度 |
| `lod` / `blur` | 磨砂。`lod` 是防混叠的预滤波，`blur` 是螺旋采样的半径——观感主要由后者决定 |
| `dark` | 压暗，边缘到中心。托住文字用的 |
| `glow` / `specular` / `shine` / `env` | accent 晕、边缘高光的强度与锐度、环境反射 |

**别靠改这些数字来试观感。** 开验收台，它把每一项都做成了开关和滑杆，改完一键导出常数：

```
bun --bun vite      然后开 http://localhost:1420/bench.html
```

验收台跑的是同一个 `startBackground`，不是副本。它还内置两张固定测试背景（实测平均亮度 0.163 / 0.798），以及一个可载入参照截图、拖动分隔线左右对比的功能。

## 三条会咬人的规则

**带玻璃的面板不能做位移入场。** 着色器拿到的是一张 CSS 像素快照，跟不了 CSS 动画——面板一边滑一边亮，玻璃就会停在旧位置。四块面板（`#search` / `#settings` / `#first` / `#ctx`）因此一律只淡入。这条现在是结构性的，不再取决于任何设置。

> 想要位移入场，正确做法不是放宽这条，是让着色器自己持有并插值矩形，DOM 只在终点淡入内容。那是 #21 的一部分。

**这份 CSS 里 ID 选择器很多，覆盖样式要盯优先级。** 已经栽过三次：`.hide` 被 `#ctx { display:flex }` 压过导致菜单关不掉；`.pill` 的状态样式被 `#searchbtn` 压过；`.panel.glassed` 匹配不到 `#ctx`（它不是 `.panel`，而且它自己的 id 规则压得住任何 class），导致着色器在右键菜单后面画了一层没人看得见的玻璃。按状态覆盖时，选择器要写到同等或更高的特异度。

**磁贴的视差要看真实尺寸再定数值。** 设计稿是 1600×900 的固定板，而网格是 `auto-fill`，磁贴实际约 148–197px 宽——比稿子里小得多。稿子上对的角度在真实尺寸上可能完全看不见（`perspective(900px)` 配 ±3° 实测边缘透视差约 0.5%）。角度可以照搬，**视距这类与尺寸成比例的量必须换算**。

## 布局是响应式的，别用固定坐标

原设计稿是 1600×900 的固定尺寸稿，所有坐标是死的。**实际运行在带鱼屏上**（实测 2600 宽以上），所以现在全部用 `clamp()` 和 `vw`。

已知未解决：**超宽屏中间是空的**。左侧详情 + 磁贴网格只有两个锚点，16:9 上填得满，21:9 上就散了。设计稿右侧原本有个助手面板（`right:56px; top:146px; width:352px`），一直没做——**它在带鱼屏上是结构性的，不是装饰**。

## 只有一个窗口

deskmind 是**一个**压在 z-order 最底的普通顶层窗口（ADR 0017）。热键唤出的 `launchpad` 浮层已经删除，代码注释里残留的"launchpad"字样是历史。

热键本身回来了，但含义变了：它不再唤出另一个窗口，而是抢焦点并打开这一个窗口里的搜索面板。**具体是哪个组合按启动时试出来的结果**——依次试 `Ctrl+Alt+D`、`Ctrl+Alt+K`、`Ctrl+Shift+D`、`Ctrl+Alt+J`，取第一个没被占用的，设置面板里显示的是实际生效的那个。不写死是因为写死已经输过两次：`Alt+Space` 是 Windows 的窗口菜单，`Ctrl+Alt+Space` 被输入法占着。

`Ctrl+Space` 与 `Alt+Shift` 永远排除：中文 Windows 上它们归输入法，而搜索框是这个应用里唯一必须能打中文的地方。

## 性能是硬约束

桌面层一天二十四小时在屏幕上，功耗特性跟网页项目完全不同。

- **被遮挡时 GPU 占用 0%，一帧都不画。** 这条不动。它不牺牲任何观感——没人在看的时候不画，用户永远感知不到
- **空闲可见（没有面板）≤ 1–2%。** 实测 1.87%
- **面板打开是第三种状态**，它需要自己的一条线，见 #16。这个状态一度是 38.25%，因为玻璃层在给整块屏幕着色而面板只占其中 2%，而且面板落定之后仍按显示器刷新率重画

**不要加持续运行的 CSS 动画到常驻元素上**——它绕过了着色器那套暂停逻辑。入场动画、hover 过渡都没问题，那些是有始有终的。

`prefers-reduced-motion` 下位移与缩放要退化成透明度变化或直接到位。首次运行那条进度条**不在**退化名单里：它是屏幕上唯一说明程序在工作的东西，冻住会停在 40% 假装自己是确定进度。
